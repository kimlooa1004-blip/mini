# PRD 1단계 — 냉장고 사진에서 식재료 인식

## 1. 목표
사용자가 올린 냉장고 사진을 이미지 모델에 보내 식재료 목록을 JSON으로 받는다. 이 결과는 2단계(레시피 생성)의 입력이 된다.

## 2. 사용자 스토리
- 사용자로서 냉장고 사진 한 장을 올리면 어떤 식재료가 있는지 목록으로 보고 싶다.
- 사용자로서 잘못 인식된 식재료를 지우거나 직접 추가해서 목록을 고치고 싶다.
- 사용자로서 사진이 아니거나 식재료가 없으면 이유를 알려 주길 원한다.

## 3. 기능 요구사항
1. 이미지 업로드: JPEG, PNG, WebP, 파일당 최대 5MB, 한 번에 1장.
2. 서버가 이미지를 base64 data URL로 바꿔 이미지 모델에 전달한다.
3. 모델 응답에서 식재료 목록(JSON)을 추출·검증해 화면에 보여 준다.
4. 사용자는 목록에서 항목을 삭제하거나 이름을 추가·수정할 수 있다. 확정된 목록이 2단계 입력이 된다.
5. 식재료 이름은 한국어 일반명으로 통일한다(예: "계란", "대파").

## 4. API 연동 기술 사양
- 모델: `nvidia/nemotron-3.5-super-vl:free` (환경변수 `OPENROUTER_IMAGE_MODEL`로 교체 가능)
- 엔드포인트: `POST https://openrouter.ai/api/v1/chat/completions`
- 인증: `Authorization: Bearer $OPENROUTER_API_KEY` (서버에서만 사용, 브라우저로 내보내지 않는다)

요청 예시
```json
{
  "model": "nvidia/nemotron-3.5-super-vl:free",
  "max_tokens": 1500,
  "messages": [{
    "role": "user",
    "content": [
      {"type": "text", "text": "이 냉장고 사진에 보이는 식재료를 한국어 일반명으로 찾아 JSON만 출력해. 형식: {\"ingredients\":[{\"name\":\"...\"}]}. 식재료가 없으면 빈 배열."},
      {"type": "image_url", "image_url": {"url": "data:image/jpeg;base64,<BASE64>"}}
    ]
  }]
}
```

응답 예시 (`choices[0].message.content`가 JSON 문자열)
```json
{"ingredients": [{"name": "계란"}, {"name": "우유"}, {"name": "대파"}]}
```

출력 스키마 (2단계로 전달)
```json
{ "ingredients": [ { "name": "string" } ] }
```
- 응답에 코드펜스나 설명 문장이 섞일 수 있으므로 첫 `{`부터 마지막 `}`까지 잘라 파싱하고, 스키마 검증에 실패하면 1회 재시도한다.

## 5. UI 흐름
업로드 화면 → (분석 중 표시) → 식재료 목록 편집 화면(삭제·추가) → "레시피 추천받기" 버튼(2단계로 이동).

## 6. 비기능 요구사항
- 에러 처리: 429(무료 모델 일시 제한)는 10초·20초 간격으로 최대 3회 재시도 후 "잠시 후 다시 시도해 주세요"를 표시한다. 404·5xx는 원인을 사용자 문구로 안내하고 상세는 서버 로그에만 남긴다.
- 보안: API 키는 `.env`에서 환경변수로만 읽는다. 키를 로그·응답·클라이언트 코드에 노출하지 않는다. 업로드 파일은 형식·크기를 서버에서 검증한다.
- 성능: 분석 응답은 최대 120초 타임아웃, 진행 상태를 표시한다.
- 무료 모델은 한도·가용성이 수시로 바뀌므로 모델 이름을 코드에 박지 않고 설정으로 둔다.

## 7. 완료 조건
- 식재료가 보이는 사진 업로드 시 목록이 JSON 스키마대로 반환된다.
- 식재료가 없는 사진, 5MB 초과 파일, 지원하지 않는 형식에서 각각 알맞은 오류 문구가 나온다.
- 모델 429 상황에서 재시도 후 성공하거나 안내 문구가 나온다.
- 키가 응답·로그·저장소에 나타나지 않는다.

## 8. 범위 외
수량·무게 추정, 유통기한 인식, 여러 장 동시 업로드, 로그인(3단계).
