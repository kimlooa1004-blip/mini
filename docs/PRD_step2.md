# PRD 2단계 — 식재료로 레시피 생성

## 1. 목표
1단계에서 확정된 식재료 목록(과 선택적으로 사용자 프로필)을 텍스트 모델에 보내 레시피 3개를 JSON으로 생성한다. 결과는 3단계에서 저장할 수 있다.

## 2. 사용자 스토리
- 사용자로서 가진 재료로 만들 수 있는 레시피를 추천받고 싶다.
- 사용자로서 각 레시피에서 있는 재료와 부족한 재료를 구분해 보고 싶다.
- 사용자로서 조리 순서를 단계별로 보고 싶다.

## 3. 기능 요구사항
1. 입력: 1단계 출력 스키마(`ingredients[].name`)와 선택 입력 `profile`(알레르기, 기피 재료, 선호 식단; 3단계 연동 전에는 빈 값).
2. 레시피 3개를 생성한다. 각 레시피는 `have`(보유 재료)와 `missing`(부족 재료)을 구분한다.
3. 프로필의 알레르기·기피 재료가 들어간 레시피는 제외한다.
4. 응답을 스키마로 검증하고, 실패하면 1회 재시도한다.
5. 결과 화면에서 레시피를 펼쳐 조리 순서를 본다.

## 4. API 연동 기술 사양
- 모델: `nvidia/nemotron-3-ultra-550b-a55b:free` (환경변수 `OPENROUTER_TEXT_MODEL`로 교체 가능)
- 엔드포인트·인증은 1단계와 동일. 추론형 모델은 생각에 토큰을 쓰므로 `max_tokens`는 1500 이상으로 둔다.

요청 예시
```json
{
  "model": "nvidia/nemotron-3-ultra-550b-a55b:free",
  "max_tokens": 3000,
  "messages": [{
    "role": "user",
    "content": "보유 재료: 계란, 우유, 대파. 알레르기: 없음. 이 재료로 만들 수 있는 한국 가정식 레시피 3개를 JSON만 출력해. 형식: {\"recipes\":[{\"title\":\"\",\"servings\":2,\"cook_time_min\":15,\"have\":[],\"missing\":[],\"steps\":[\"\"]}]}"
  }]
}
```

응답 예시 (`choices[0].message.content`가 JSON 문자열)
```json
{"recipes":[{"title":"대파 계란말이","servings":2,"cook_time_min":15,
 "have":["계란","대파"],"missing":["식용유"],
 "steps":["대파를 잘게 썬다","계란에 대파와 소금을 넣어 푼다","약불에서 말아 익힌다"]}]}
```

출력 스키마 (3단계 저장 형식과 동일)
```json
{ "recipes": [ { "title": "string", "servings": 0, "cook_time_min": 0,
                 "have": ["string"], "missing": ["string"], "steps": ["string"] } ] }
```

## 5. UI 흐름
1단계에서 넘어온 재료 목록 확인 → 레시피 생성 중 표시 → 레시피 3개 카드(보유/부족 재료 배지) → 카드 펼침(조리 순서) → "저장" 버튼(3단계).

## 6. 비기능 요구사항
- 에러 처리: 1단계와 같은 429 재시도·안내 정책. 모델이 스키마에 맞지 않는 응답을 두 번 연속 내면 "레시피를 만들지 못했습니다"와 다시 시도 버튼을 보여 준다.
- 보안: 키는 서버에서만 사용한다. 사용자가 입력한 재료명·프로필은 프롬프트에 넣기 전에 길이(항목당 50자, 최대 50개)와 문자 종류를 검증해 프롬프트 주입을 줄인다.
- 모델 이름은 설정으로 두고, 모델이 막히면 설정만 바꿔 대체한다.

## 7. 완료 조건
- 재료 목록으로 스키마에 맞는 레시피 3개가 생성된다.
- 알레르기 재료가 든 레시피가 결과에 없다.
- `have`는 입력 재료의 부분집합이고 `missing`은 입력에 없는 재료이다.
- 모델 오류·429에서 재시도 또는 안내 문구가 나온다.

## 8. 범위 외
영양 성분 계산, 레시피 이미지 생성, 가격·구매 연동, 저장(3단계).
