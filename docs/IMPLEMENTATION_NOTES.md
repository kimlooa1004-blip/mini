# 구현 노트 — PRD와 달라진 점

| PRD | 구현 | 이유 |
|---|---|---|
| 1단계 이미지 모델 `google/gemma-4-26b-a4b-it:free` 등 | 기본 `nvidia/nemotron-3.5-super-vl:free` | 직접 호출해 통과한 모델. Google 계열 무료 모델은 429가 계속 났다 |
| 2단계 텍스트 모델 `nemotron-3-super-120b` 등 | 기본 `nvidia/nemotron-3-ultra-550b-a55b:free` | 앞의 모델은 제공업체가 404를 반환했다 |
| 1단계 범위 외: 수량 | 식재료 표에 수량·단위 열을 추가해 프롬프트에 반영 | 사용성 개선 |
| 재시도 1회 + 폴백 | 기본 모델 최대 3회(대기 2초·4초) 후 다른 제공업체 모델로 폴백 | 무료 모델 429 대응 |
| 3단계 REST API 표(`/api/...`) | Streamlit 함수 호출(`db.py`, `auth.py`)로 구현 | Streamlit은 화면과 서버가 한 프로세스라 별도 API가 필요 없다 |
| 3단계 인증 | 이메일·비밀번호(bcrypt) + SQLite. 구글 로그인·Supabase는 미구현 | 계정·OAuth 값이 없고 이 환경에서 만들 수 없다 |
| 로그인 시도 제한(IP·계정별) | 계정(이메일)별, 프로세스 메모리 | 앱 재시작 시 초기화된다. IP 기준은 Streamlit에서 신뢰할 값이 없다 |
| 알레르기 재료가 든 레시피 제외 | 프롬프트에 금지 재료를 알리고, 응답도 코드가 한 번 더 걸러낸다 | 모델이 지시를 어길 수 있어서 |

## 알려진 한계
- 새로고침하면 로그아웃된다(세션이 서버 메모리). 로그인 유지(쿠키)는 미구현.
- SQLite 파일(`data/app.db`)은 Streamlit Cloud에서 재부팅·재배포 시 초기화될 수 있다. 실사용 전 외부 DB로 옮긴다.
- 모델이 만든 레시피 텍스트는 그대로 화면에 표시한다(HTML은 렌더하지 않지만 마크다운 서식은 적용된다).
- 사진은 축소한 뒤 OpenRouter(와 모델 제공업체)로 전송된다. 개인 정보가 담긴 사진은 올리지 않는다.
- 실제 OpenRouter 호출은 개발 환경에서 확인하지 못했다. `scripts/test_openrouter.py`와 앱으로 PC에서 확인한다.
